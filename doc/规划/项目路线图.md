# 项目路线图

> 项目：My Tools Web  
> 当前阶段：功能型 MVP 已完成，发布工程待闭环  
> 最近核对：2026-08-21

## 项目目标

- 提供无需登录、无广告、纯前端运行的在线工具箱。
- 用户输入默认只在浏览器本地处理，不依赖业务后端。
- 保持工具注册、页面路由和元数据结构可扩展。
- 建立可重复执行的测试、部署和版本发布流程。

## 当前状态

| 领域 | 状态 | 说明 |
| --- | --- | --- |
| 核心功能 | 基本完成 | 已注册 16 个工具，覆盖开发、文本、设计、图片和通用场景 |
| 搜索与导航 | 基本完成 | 支持名称、说明、关键字、标签、分类以及 `cat:`、`tag:` 语法 |
| 安全与兼容 | 部分完成 | JWT base64url、Markdown 输出净化和 SPA 回退已经实现 |
| 自动检查 | 部分完成 | 自定义元数据、搜索、界面结构、主题顺序和兼容性检查可运行 |
| 正式测试 | 未完成 | 尚未接入 Vitest、组件测试和浏览器端回归测试 |
| 自动部署 | 未完成 | Vercel 配置已存在；GitHub Pages 工作流及项目路径适配尚未完成 |
| 发布管理 | 未完成 | `package.json` 仍为 `0.0.0`，尚无正式 Tag 和 Release |

## 已交付能力

### 工具能力

- JSON、Base64、URL、时间戳和进制转换
- 文本处理、文本差异、正则表达式测试
- Hash、JWT、Markdown 预览
- 二维码、颜色转换、图片压缩
- 密码生成和单位换算

### 平台能力

- 工具注册表自动生成路由
- 首页搜索、分类展示和最近使用记录
- 深色模式、Toast、404 页面和隐私页面
- 工具元数据质量检查
- 搜索及兼容性冒烟检查
- Vercel SPA 重写和 GitHub Pages 回退文件

## 后续里程碑

### 里程碑一：文档治理

状态：已完成。

- 建立 `doc/` 文档目录和中文分类。
- 合并过期计划与重复任务状态。
- 保留独立的路线图、代码执行计划、质量清单和历史记录。
- 根目录只保留项目入口文档与工具约定文件。

### 里程碑二：部署闭环

优先级：P0。

- 增加 GitHub Pages 专用构建命令。
- 配置 Vite `/tools/` 基础路径。
- 路由使用 `import.meta.env.BASE_URL`。
- 修复项目站点下的 404 深链接回退。
- 新增 GitHub Pages 自动部署工作流。

完成标准：公开站点首页和任意工具深链接均可直接访问及刷新。

### 里程碑三：测试与持续集成

优先级：P0。

- 使用 Vitest 覆盖核心纯函数和异常输入。
- 使用 Vue Test Utils 验证关键组件交互。
- 使用 Playwright 覆盖首页、搜索、主题、工具跳转和深链接。
- 新增 GitHub Actions 持续集成工作流。

完成标准：推送和拉取请求自动执行检查、测试与构建，核心逻辑覆盖率达到 80%。

### 里程碑四：Loop5 验收闭环

优先级：P1。

- 在 20 个以上工具数据规模下执行搜索性能基准。
- 搜索响应 P95 小于 150ms。
- 补充人工界面验收结果、截图或自动化产物。
- 统一剩余的中英文混用文案。

完成标准：质量清单无阻塞项，执行结果可复现。

### 里程碑五：正式版本发布

优先级：P1。

- 确定第一个公开稳定版本号。
- 更新 `package.json` 和锁文件版本。
- 建立变更日志、Git Tag 和 GitHub Release。
- 在 README 中补充正式在线地址。

完成标准：源码、文档、部署产物和版本记录一致。

## 已知风险

- 当前 GitHub Pages 项目地址尚未上线，现有配置不能代表线上验证通过。
- 自定义检查脚本主要验证逻辑和源码结构，不能替代真实浏览器测试。
- 当前只有 16 个工具，尚未满足 Loop5 的 20+ 工具性能验收规模。
- 图片压缩等页面仍有英文文案，与默认中文界面不完全一致。
- Markdown 输出净化属于安全敏感逻辑，需要固定攻击样例测试防止回归。
