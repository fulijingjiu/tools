# 代码执行计划

> 状态：已规划，暂停开发  
> 启动条件：完成文档整理并由维护者确认  
> 原则：按阶段实施，每个阶段独立验证和提交

## 阶段一：GitHub Pages 部署

优先级：P0。

涉及文件：

- `package.json`
- `vite.config.ts`
- `src/router/index.ts`
- `public/404.html`
- `.github/workflows/deploy-pages.yml`

执行内容：

1. 拆分类型检查、默认构建和 GitHub Pages 构建命令。
2. GitHub Pages 构建使用 `/tools/` 基础路径。
3. Vue Router 使用 `import.meta.env.BASE_URL`。
4. 404 回退保留并恢复原始深链接。
5. 增加 GitHub Pages 自动部署工作流。
6. 保持 Vercel 根路径构建不受影响。

验收：站点首页返回 200，工具深链接可直接进入和刷新。

## 阶段二：单元与组件测试

优先级：P0。

计划引入：

- Vitest
- jsdom
- Vue Test Utils
- V8 Coverage

优先覆盖：

- Base64 中文和非法输入
- URL 特殊字符
- JSON 格式化和异常内容
- JWT base64url、缺段和非法字符
- Markdown 危险标签与事件属性
- 密码长度和字符类型边界
- 搜索分类、标签、排序和特殊符号
- 工具路由与别名

验收：核心逻辑覆盖率达到 80%，异常输入不产生未捕获错误。

## 阶段三：浏览器回归与持续集成

优先级：P0。

执行内容：

- 使用 Playwright 检查首页、搜索、主题、工具跳转和深链接。
- 覆盖桌面端和移动端基础视口。
- 失败时保存截图、控制台日志和 Trace。
- 新增 GitHub Actions 持续集成工作流。
- 在推送和拉取请求中执行检查、测试及构建。

验收：每次代码变更都有可追踪的自动化结果。

## 阶段四：性能和 Loop5 闭环

优先级：P1。

执行内容：

- 构造至少 32 个工具的稳定测试数据。
- 对搜索进行预热和多轮基准测试。
- 输出平均耗时和 P95。
- 将 P95 小于 150ms 设为验收门槛。
- 保存人工验收或 Playwright 产物。
- 更新路线图和回归清单。

## 阶段五：文案统一

优先级：P1。

执行内容：

- 将图片压缩页面的默认英文文案改为中文。
- 清理 `unchanged` 等中英混用说明。
- 统一首页搜索、404 和匹配原因文案。
- 执行全仓库 UTF-8 编码检查。

## 阶段六：正式版本发布

优先级：P1。

执行内容：

1. 确认首个公开稳定版本号。
2. 同步更新 `package.json` 和锁文件。
3. 新增变更日志。
4. 更新 README 在线地址。
5. 创建 Git Tag 和 GitHub Release。
6. 执行上线前及上线后检查。

## 推荐提交顺序

```text
fix: support github pages base path
ci: add github pages deployment workflow
test: add core utility unit tests
test: add browser regression coverage
perf: add search performance benchmark
fix: unify interface copy
docs: close loop5 acceptance records
chore: prepare first stable release
```

## 实施约束

- 不在同一提交中混合部署、测试和产品功能修改。
- 每阶段完成后先运行相应检查，再进入下一阶段。
- 不覆盖用户未提交的改动。
- 部署成功前不把路线图中的部署状态标记为完成。
- 正式发布前必须满足[回归检查清单](../质量/回归检查清单.md)。
